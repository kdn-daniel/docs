The EcoRPA REST API gives you programmatic access to your automation platform — letting you build, manage, and monitor workflows, tasks, and third-party integrations from any application or service. This reference covers everything you need to make your first request and explore every available resource.

## Base URL

All API requests are made to the following base URL:

```text
https://api.ecorpa.com/v1
```

Include this as the root of every endpoint path you call. For example, to list your workflows you would call `https://api.ecorpa.com/v1/workflows`.

## Authentication

EcoRPA uses API keys to authenticate requests. Pass your API key in the `Authorization` header of every request using the Bearer scheme:

```http
Authorization: Bearer YOUR_API_KEY
```

Keep your API key secret — never expose it in client-side code or public repositories. To learn how to generate and manage API keys, see the [Authentication](/authentication) page.

## API Versioning

The current API version is `v1`. The version identifier is embedded directly in the URL path, so all requests you make today are explicitly scoped to `v1`:

```text
https://api.ecorpa.com/v1/<resource>
```

EcoRPA provides **at least 12 months notice** before deprecating any API version. When a new version is released, the previous version continues to function until its deprecation window closes. Monitor your registered email and the changelog for deprecation announcements.

## Content Type

All request bodies must be encoded as JSON, and all response bodies are returned as JSON. Set the following header on every request that includes a body:

```http
Content-Type: application/json
```

Requests submitted with an incorrect or missing `Content-Type` header will be rejected with a `415 Unsupported Media Type` response.

## Example Request and Response

The example below retrieves all workflows in your account using a `GET` request to `/v1/workflows`.

**Request**

```bash
curl --request GET \
  --url https://api.ecorpa.com/v1/workflows \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json"
```

**Response**

```json
{
  "data": [
    {
      "id": "wf_01j9kz2p8xqr4nt6ms7b",
      "name": "Invoice Processing",
      "status": "active",
      "trigger": "webhook",
      "created_at": "2024-03-15T10:22:00Z",
      "updated_at": "2024-11-08T14:05:31Z"
    },
    {
      "id": "wf_01j9kz3a7yvs5ou8lt4c",
      "name": "Employee Onboarding",
      "status": "draft",
      "trigger": "schedule",
      "created_at": "2024-07-02T08:44:17Z",
      "updated_at": "2024-10-19T09:30:00Z"
    }
  ],
  "meta": {
    "total": 2,
    "page": 1,
    "per_page": 20
  }
}
```

A successful response returns HTTP `200 OK` with a `data` array of workflow objects and a `meta` object containing pagination details.
