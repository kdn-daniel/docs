Todos los módulos tienen webhook. Hay una URL por cliente. Cuando el lote termina, ECORPA hace `POST` a esa URL con el mismo `Data` del `GET`, más `Modulo` e `IdSolicitud`. Sin URL, el resultado se consulta con `GET`.

## Registrar la URL

`PUT https://apis.ecorpa.com/v2/notificaciones` con la API Key.

```bash
curl -sS -X PUT "https://apis.ecorpa.com/v2/notificaciones" \
  -H "Authorization: Bearer ecorpa_key_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"Url":"https://integrador.example/ecorpa"}'
```

La respuesta incluye `Data.Secreto` una sola vez. Guárdalo: con él se verifica la firma de cada aviso.

`GET /v2/notificaciones` muestra `Url` y `Activa`, sin el secreto.

`DELETE /v2/notificaciones` apaga el aviso. El cliente vuelve a consultar con `GET`.

## Reglas

- Una URL por cliente, para todos los módulos.
- La URL es HTTPS, sin usuario ni contraseña en la dirección, y tiene que resolver a una IP pública.
- El aviso sale al cerrar el lote, en éxito y en error.
- `Data` es el mismo objeto del `GET` de ese módulo.
- Responde `2xx` para confirmar la recepción.
- Un `4xx` distinto de `408` y `429` no se reintenta.
- Fallos de red, `408`, `429` y `5xx` se reintentan con espera creciente (5 s, 10 s, 20 s, 40 s). A la quinta vez se deja de intentar.
- `X-Ecorpa-Delivery` se repite en los reintentos del mismo aviso. Sirve para no procesarlo dos veces.
- El `GET` de estado sigue disponible. Mínimo 10 segundos entre dos consultas del mismo `IdSolicitud`. Máximo 30 `GET` por minuto por cliente. Si se pasa, la respuesta es `429` y `Retry-After` indica los segundos de espera.

`Modulo` en el aviso:

| `Modulo` | Qué es |
| --- | --- |
| `consulta_seguridad_social` | Consulta de seguridad social |
| `consulta_antecedentes` | Consulta de antecedentes |
| `formularios_afiliacion` | Formularios de afiliación |
| `afiliaciones_seguridad_social` | Afiliaciones de seguridad social |

```json
{
  "Modulo": "formularios_afiliacion",
  "IdSolicitud": "<uuid>",
  "Success": true,
  "Message": "Consulta de solicitud recuperada.",
  "Data": {}
}
```

## Seguridad

- Registrar, consultar y apagar la URL exige API Key (`Authorization: Bearer ecorpa_key_…`).
- Rechazamos HTTP, localhost, redes privadas y la dirección de metadata de la nube. Tampoco seguimos redirecciones.
- El secreto no vuelve a salir en el `GET`.
- Cada `POST` trae `X-Ecorpa-Signature`: `sha256=` más el HMAC-SHA256 del cuerpo crudo, calculado con ese secreto. Hay que firmar los bytes recibidos, sin volver a serializar el JSON.
- El aviso espera como máximo 8 segundos. Un fallo de tu servidor no detiene el procesamiento del lote.
