Para llamar las APIs de integración solo necesitas tu **API Key**. No envíes `UserId` ni `CorreoCliente` en el body: con la key ya sabemos quién eres.

## Header

```http
Authorization: Bearer ecorpa_key_xxxxxxxx
Content-Type: application/json
```

- Tu key empieza por `ecorpa_key_…`
- Te la entregamos al activar la integración
- Guárdala en el backend o en un gestor de secretos. Nunca en el front ni en un repo público

## Ejemplo rápido

```bash
curl -sS -X GET "https://apis.ecorpa.com/v2/consulta/seguridad_social/{IdSolicitud}" \
  -H "Authorization: Bearer ecorpa_key_xxxxxxxx"
```

## Scopes

Cada producto pide su propio permiso. Si la key no lo tiene, la llamada no pasa.

| Producto | Scope |
| --- | --- |
| Consulta seguridad social | `consultas_seguridad_social` |
| Consulta antecedentes | `consulta_antecedentes` |
| Formularios de afiliación | `formularios_afiliacion` |
| Afiliaciones seguridad social | `afiliaciones_seguridad_social` |

## Si algo falla al autenticar

| HTTP | Qué suele pasar |
| --- | --- |
| `401` | Falta la key, está mal escrita o ya no es válida |
| `403` | La key sirve, pero no tiene permiso para ese producto |

## Buenas prácticas

<Warning>
  No pongas la API Key en JavaScript del navegador, en apps móviles ni en repositorios públicos.
</Warning>

- Cárgala desde una variable de entorno (por ejemplo `ECORPA_API_KEY`)
- Si se filtró, rótala de una vez
- Pide solo los scopes que realmente uses
- Revoca las keys que ya no necesites
