EcoRPA uses standard HTTP status codes to indicate the outcome of every API request. When a request fails, the API also returns a structured JSON error body that gives you a machine-readable error code, a human-readable message, and a unique request identifier you can use for troubleshooting. Understanding this format lets you build error handling that is precise, actionable, and easy to debug.

## Error Response Format

Every error response follows the same envelope structure. The `error` object contains all the information you need to identify the problem and decide how to respond in your application.

```json
{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "The requested workflow was not found.",
    "status": 404,
    "request_id": "req_abc123"
  }
}
```

<Note>
  Save the `request_id` value whenever you log an error. When you contact EcoRPA support, providing this ID allows the support team to retrieve the exact request from the platform logs and diagnose the issue far more quickly than searching by timestamp or endpoint alone.
</Note>

## HTTP Status Codes

The table below lists every HTTP status code the EcoRPA API returns, along with its meaning and when you can expect to see it.

| Status | Name | When you see it |
|---|---|---|
| `200` | OK | The request succeeded and the response body contains the result. |
| `201` | Created | A new resource was created successfully. |
| `204` | No Content | The request succeeded but there is no body to return (for example, after a DELETE). |
| `400` | Bad Request | The request was malformed or missing required parameters. |
| `401` | Unauthorized | The `Authorization` header is missing or the API key is invalid. |
| `403` | Forbidden | Your API key is valid but does not have permission to perform this action. |
| `404` | Not Found | The requested resource does not exist. |
| `409` | Conflict | The request conflicts with the current state of the resource (for example, a duplicate name). |
| `422` | Unprocessable Entity | The request body was syntactically valid but failed semantic validation rules. |
| `429` | Too Many Requests | You have exceeded the rate limit. Retry after the duration specified in the `Retry-After` header. |
| `500` | Internal Server Error | An unexpected error occurred on EcoRPA's servers. Retry with exponential backoff. |

## Error Codes

In addition to HTTP status codes, EcoRPA returns a platform-specific `code` string in the error body. Use this code in your error-handling logic to react to specific failure modes without parsing the human-readable `message` field.

| Code | HTTP Status | Description |
|---|---|---|
| `INVALID_REQUEST` | 400 | The request is missing required fields or contains unsupported parameters. |
| `AUTHENTICATION_FAILED` | 401 | The API key provided is missing, expired, or does not match any active key. |
| `PERMISSION_DENIED` | 403 | The authenticated account does not have the required permissions for this operation. |
| `RESOURCE_NOT_FOUND` | 404 | The resource identified by the given ID does not exist in your account. |
| `CONFLICT` | 409 | The operation cannot be completed because it would create a conflict with existing data. |
| `VALIDATION_ERROR` | 422 | One or more fields in the request body failed validation. Check the `message` for field-level details. |
| `RATE_LIMIT_EXCEEDED` | 429 | Your account has sent too many requests in a short period. Back off and retry. |
| `INTERNAL_ERROR` | 500 | An unexpected error occurred on the EcoRPA platform. Contact support if the issue persists. |

## Handling Errors

The examples below demonstrate a consistent error-handling pattern for EcoRPA API responses in Python and JavaScript. In both cases, the code inspects the error `code` field to apply the correct recovery strategy for each failure type.

<CodeGroup>

```python Python
import os
import time
import requests

api_key = os.environ["ECORPA_API_KEY"]
base_url = "https://api.ecorpa.com/v1"
headers = {
    "Authorization": f"Bearer {api_key}",
    "Accept": "application/json",
}

def get_workflow(workflow_id):
    response = requests.get(f"{base_url}/workflows/{workflow_id}", headers=headers)

    if response.ok:
        return response.json()["data"]

    error = response.json().get("error", {})
    code = error.get("code")
    request_id = error.get("request_id")

    if code == "RESOURCE_NOT_FOUND":
        raise ValueError(f"Workflow {workflow_id} does not exist.")
    elif code == "AUTHENTICATION_FAILED":
        raise PermissionError("Invalid or missing API key. Check your ECORPA_API_KEY.")
    elif code == "RATE_LIMIT_EXCEEDED":
        retry_after = int(response.headers.get("Retry-After", 5))
        print(f"Rate limit hit. Retrying in {retry_after}s... (request_id: {request_id})")
        time.sleep(retry_after)
        return get_workflow(workflow_id)
    else:
        raise RuntimeError(f"API error [{code}]: {error.get('message')} (request_id: {request_id})")
```

```javascript JavaScript
const axios = require("axios");

const client = axios.create({
  baseURL: "https://api.ecorpa.com/v1",
  headers: {
    Authorization: `Bearer ${process.env.ECORPA_API_KEY}`,
    Accept: "application/json",
  },
});

async function getWorkflow(workflowId) {
  try {
    const response = await client.get(`/workflows/${workflowId}`);
    return response.data.data;
  } catch (err) {
    if (!err.response) throw err; // network error

    const { code, message, request_id } = err.response.data.error ?? {};

    switch (code) {
      case "RESOURCE_NOT_FOUND":
        throw new Error(`Workflow ${workflowId} does not exist.`);
      case "AUTHENTICATION_FAILED":
        throw new Error("Invalid or missing API key. Check your ECORPA_API_KEY.");
      case "RATE_LIMIT_EXCEEDED": {
        const retryAfter = parseInt(err.response.headers["retry-after"] ?? "5", 10);
        console.warn(`Rate limit hit. Retrying in ${retryAfter}s... (request_id: ${request_id})`);
        await new Promise((resolve) => setTimeout(resolve, retryAfter * 1000));
        return getWorkflow(workflowId);
      }
      default:
        throw new Error(`API error [${code}]: ${message} (request_id: ${request_id})`);
    }
  }
}
```
