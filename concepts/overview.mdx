This section introduces the foundational building blocks of the EcoRPA API. Before you start making requests, understanding how workflows, tasks, integrations, and webhooks relate to one another will help you design automations that are reliable, maintainable, and easy to extend.

## The EcoRPA Data Model

Every automation you build in EcoRPA is expressed through four core resource types. Each type has its own set of API endpoints, but they are designed to work together as a unified system. The diagram below shows what each resource represents from your perspective as a developer.

<CardGroup cols={2}>
  <Card title="Workflows" icon="bolt">
    A workflow is the top-level container for an automation. It defines the trigger conditions, the sequence of steps to execute, and the overall lifecycle of a process. You create and manage workflows to orchestrate everything else in EcoRPA.
  </Card>
  <Card title="Tasks" icon="list-check">
    A task represents a single unit of work inside a workflow — such as sending an email, transforming data, or calling an external API. Tasks are executed in the order you define, and each task can pass its output to the next step in the sequence.
  </Card>
  <Card title="Integrations" icon="plug">
    An integration connects EcoRPA to a third-party service, such as Slack, Salesforce, or Google Sheets. Once you configure an integration, any workflow can use it as a data source or action target without re-entering credentials for every task.
  </Card>
  <Card title="Webhooks" icon="bell">
    A webhook allows EcoRPA to notify your systems in real time when something happens — for example, when a workflow completes or a task fails. You register a webhook endpoint on your server, and EcoRPA will send an HTTP POST with event details whenever the chosen event fires.
  </Card>
</CardGroup>

## How They Connect

These four resource types are not independent — they form a deliberate hierarchy. A workflow is the starting point; tasks give it behavior; integrations give tasks access to external services; and webhooks give you visibility into what is happening at every stage. The flow below shows the typical path from initial setup to active monitoring.

<Steps>
  <Step title="Create a Workflow">
    Start by creating a workflow object. Set its name, description, and trigger type (for example, a scheduled cron trigger or an inbound webhook trigger). The workflow acts as the container that holds everything else together.
  </Step>
  <Step title="Add Tasks">
    Add one or more tasks to your workflow. Define the action each task performs, its input parameters, and any conditional logic that controls whether it runs. Tasks execute in the order you specify, and you can pass output from one task as input to the next.
  </Step>
  <Step title="Configure Integrations">
    If any of your tasks interact with a third-party service, attach an integration to provide the necessary credentials and connection settings. EcoRPA securely stores your integration credentials so your workflow can authenticate with external APIs on your behalf.
  </Step>
  <Step title="Monitor via Webhooks">
    Register a webhook to receive real-time event notifications as your workflow runs. Subscribe to events such as `workflow.completed`, `task.failed`, or `workflow.paused` so your systems can react immediately without polling the API for status updates.
  </Step>
</Steps>
