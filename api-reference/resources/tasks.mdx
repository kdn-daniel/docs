Tasks are the individual steps executed within a workflow. Each task represents a discrete unit of work — such as calling an external API, evaluating a condition, or sending a notification — and runs in the order defined by the parent workflow. You manage tasks independently through the Tasks API, giving you precise control over the logic and data flow inside each workflow.

## The Task Object

Every task response includes the following fields.

```json
{
  "id": "tsk_09ABCDE012FGH345IJK678LMN",
  "workflow_id": "wf_01HXYZ9ABC123DEF456GHI789",
  "name": "Validate Invoice Fields",
  "type": "condition",
  "status": "completed",
  "input": {
    "field": "invoice_total",
    "operator": "greater_than",
    "value": 0
  },
  "output": {
    "result": true,
    "matched_branch": "non_zero_invoice"
  },
  "created_at": "2024-03-15T08:31:00Z",
  "completed_at": "2024-03-15T08:31:02Z"
}
```

<ResponseField name="id" type="string">
  The unique identifier for the task, assigned by EcoRPA at creation time.
</ResponseField>

<ResponseField name="workflow_id" type="string">
  The identifier of the workflow this task belongs to.
</ResponseField>

<ResponseField name="name" type="string">
  A human-readable label for the task, describing what it does within the workflow.
</ResponseField>

<ResponseField name="type" type="string">
  The category of work this task performs. Accepted values are `action` (executes an operation), `condition` (evaluates a logical branch), and `trigger` (initiates the workflow in response to an event).
</ResponseField>

<ResponseField name="status" type="string">
  The current execution state of the task. Possible values are `pending` (not yet started), `running` (actively executing), `completed` (finished successfully), and `failed` (terminated with an error).
</ResponseField>

<ResponseField name="input" type="object">
  A free-form JSON object containing the configuration or data passed into the task at runtime. The shape of this object depends on the task `type` and the specific operation being performed.
</ResponseField>

<ResponseField name="output" type="object">
  A free-form JSON object containing the result data produced by the task after execution. This field is `null` while the task is in `pending` or `running` status.
</ResponseField>

<ResponseField name="created_at" type="string">
  The ISO 8601 timestamp indicating when the task was created.
</ResponseField>

<ResponseField name="completed_at" type="string">
  The ISO 8601 timestamp indicating when the task finished executing. This field is `null` for tasks that have not yet reached a terminal status (`completed` or `failed`).
</ResponseField>

## Endpoints

<Accordion title="GET /v1/tasks — List tasks">

Retrieve a paginated list of tasks. You must supply the `workflow_id` query parameter to scope results to a specific workflow.

### Query Parameters

<ParamField query="workflow_id" type="string" required>
  The identifier of the workflow whose tasks you want to list.
</ParamField>

<ParamField query="status" type="string">
  Filter tasks by execution status. Accepted values are `pending`, `running`, `completed`, and `failed`. Omit this parameter to return tasks in all statuses.
</ParamField>

<ParamField query="page" type="integer">
  The page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  The number of tasks to return per page. Defaults to `20`. Maximum value is `100`.
</ParamField>

### Request

```bash
curl --request GET \
  --url "https://api.ecorpa.com/v1/tasks?workflow_id=wf_01HXYZ9ABC123DEF456GHI789&status=completed&page=1&per_page=2" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

### Response

<Accordion title="POST /v1/tasks — Create a task">

Create a new task and attach it to a workflow. The task is added to the end of the workflow's execution sequence by default.

### Body Parameters

<ParamField body="workflow_id" type="string" required>
  The identifier of the workflow this task will belong to.
</ParamField>

<ParamField body="name" type="string" required>
  A descriptive label for the task. Must be between 1 and 255 characters.
</ParamField>

<ParamField body="type" type="string" required>
  The category of work this task performs. Accepted values are `action`, `condition`, and `trigger`.
</ParamField>

<ParamField body="input" type="object">
  A JSON object containing the initial configuration or input data for the task. The expected shape depends on the task `type`.
</ParamField>

### Request

```bash
curl --request POST \
  --url "https://api.ecorpa.com/v1/tasks" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "workflow_id": "wf_01HXYZ9ABC123DEF456GHI789",
    "name": "Notify Legal Team",
    "type": "action",
    "input": {
      "channel": "slack",
      "recipient": "#legal-alerts",
      "message": "A new contract has been submitted for review."
    }
  }'
```

### Response `201 Created`

```json
{
  "data": {
    "id": "tsk_11BCDEF456GHI789JKL012MNO",
    "workflow_id": "wf_01HXYZ9ABC123DEF456GHI789",
    "name": "Notify Legal Team",
    "type": "action",
    "status": "pending",
    "input": {
      "channel": "slack",
      "recipient": "#legal-alerts",
      "message": "A new contract has been submitted for review."
    },
    "output": null,
    "created_at": "2024-06-15T11:05:00Z",
    "completed_at": null
  }
}
```

</Accordion>

<Accordion title="PATCH /v1/tasks/{id} — Update a task">

Update the `status` or `input` of an existing task. Use this endpoint to manually advance a stalled task, correct input data before a retry, or mark a task as failed after external investigation. Supply only the fields you want to change.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the task you want to update.
</ParamField>

### Body Parameters

<ParamField body="status" type="string">
  The new status for the task. Accepted values are `pending`, `running`, `completed`, and `failed`. Note that transitioning a task to `running` from `completed` or `failed` is not permitted; create a new task instead.
</ParamField>

<ParamField body="input" type="object">
  A JSON object that replaces the task's existing `input` configuration. This is useful for correcting parameters before a retry.
</ParamField>

### Request

```bash
curl --request PATCH \
  --url "https://api.ecorpa.com/v1/tasks/tsk_11BCDEF456GHI789JKL012MNO" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "status": "pending",
    "input": {
      "channel": "slack",
      "recipient": "#legal-review",
      "message": "A new contract has been submitted for urgent review."
    }
  }'
```

### Response

```json
{
  "data": {
    "id": "tsk_11BCDEF456GHI789JKL012MNO",
    "workflow_id": "wf_01HXYZ9ABC123DEF456GHI789",
    "name": "Notify Legal Team",
    "type": "action",
    "status": "pending",
    "input": {
      "channel": "slack",
      "recipient": "#legal-review",
      "message": "A new contract has been submitted for urgent review."
    },
    "output": null,
    "created_at": "2024-06-15T11:05:00Z",
    "completed_at": null
  }
}
```

</Accordion>
